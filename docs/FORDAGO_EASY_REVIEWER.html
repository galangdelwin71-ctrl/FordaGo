1. Core System Overview

FordaGO is an automated gym management, real-time coaching, and optical turnstile QR access platform built specifically for AFFORDA Gym in Cabiao, Nueva Ecija. It eliminates paper-based attendance, prevents lost revenue from uncollected dues, provides interactive exercise guidance, and connects members directly with coaches.

⚡ Before vs. After FordaGO • Before: Manual paper logbooks, unverified pass sharing, informal unorganized coaching, manual headcount inventory, and error-prone paper calculations.
• After: Sub-second QR turnstile check-ins, in-chat structured workout proposals, automatic inventory synchronization during checkout, and 1-click vector PDF financial reports.

3. User Roles & Permissions

• Member: Regular client. Generates QR entry pass, tracks PRs, views equipment tutorials, chats with coaches, and orders supplements.
• Coach: Accredited trainer. Manages clients, sends workout proposals with fees in chat, creates group classes, and tracks monthly earnings.
• Employee: Front-desk staff. Scans member QR passes, confirms/rejects check-ins, and verifies GCash/Cash orders.
• Super Admin: Owner & Lead Administrator. Full authority over coach accounts, equipment tutorials, membership fees, and financial PDF analytics.

7. High-Yield Defense Q&A Master Script

Q1: What is the main objective of FordaGO?
Answer: FordaGO was developed to completely modernize and digitize the manual operations of AFFORDA Gym in Cabiao, Nueva Ecija. It eliminates paper logbooks, automates QR turnstile access, provides on-demand equipment tutorials, empowers coaches to monetize workout plans, and automates supplement inventory and financial reporting.
Q2: Why did you choose Ionic 8 and Angular 18 for the frontend?
Answer: Ionic 8 combined with Angular 18 allowed our team to maintain a single unified codebase that compiles simultaneously into a high-performance native Android APK (via Capacitor) and a responsive desktop web application. Angular provides enterprise-grade structure with strong TypeScript typing and modular Route Guards, while Ionic delivers pre-built mobile UI components with native swipe gestures.
Q3: How does the system prevent race conditions when two members buy the last supplement item at the same time?
Answer: The system utilizes ACID Database Transactions paired with Pessimistic Row-Level Locking (lockForUpdate() in Laravel). When a checkout begins, the database locks that specific product row. The second checkout waits until the first finishes. Once stock reaches zero, the second checkout cleanly returns an "Out of Stock" error, preventing negative inventory.
Q4: How does the Turnstile Scanner prevent members from sharing their QR pass with friends?
Answer: The system implements a server-side Anti-Pass-Sharing algorithm. When a QR code is scanned, the server checks both membership expiry and the timestamp of the last check-in. If the same QR code is presented again within a lockout window, the scanner flags it as a duplicate access violation and alerts staff.
Q5: Why does GitHub display 82.8% TypeScript and only 4.2% PHP?
Answer: GitHub Linguist analyzes only custom tracked source code in the repository. In Angular 18, every screen requires separate TypeScript files for components, services, route guards, and data models across 30+ pages. In contrast, the vast codebase of Laravel Framework and Reverb resides inside the vendor/ directory (which is excluded via .gitignore). The 4.2% PHP represents our custom business logic, 21 controllers, and 120+ REST endpoints written with high expressiveness.
Q6: How does real-time communication work in FordaGO?
Answer: FordaGO runs a dedicated WebSocket server using Laravel Reverb on port 8080. When a user sends a chat message or creates a workout proposal, Laravel broadcasts an event to private, authorized WebSocket channels. Connected clients running Laravel Echo receive and render the payload in under 50 milliseconds without polling or manual page refreshing.
Q7: What is the purpose of Docker in your deployment strategy?
Answer: Docker containerization packages the entire application ecosystem (MySQL, PHP-FPM API, Reverb WebSocket, Queue Worker, Frontend SPA, and Nginx Gateway) into isolated, portable environments. This eliminates the "it works on my machine" problem, ensuring identical behavior across local development laptops, testing environments, and the cloud production VPS.
Q8: What statistical results did FordaGO achieve during the ISO/IEC 25010 evaluation?
Answer: FordaGO attained an overall grand mean of 3.80 out of 4.00, interpreted as "Strongly Agree / Highly Acceptable." IT Experts rated the system at 3.75, Gym Staff and Coaches rated it at 3.84, and Gym Members rated it at 3.82, confirming that the system excels in functional suitability, performance, compatibility, usability, and security.
